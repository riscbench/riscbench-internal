\section{Technical Description}
This deliverable defines the scope boundary for Phase-2 so contributors can distinguish adapter logic from shared engine logic and execute the correct validation path before merge.

\section{Implementation Fulfillment}
Primary references are \codepath{Phase-2/README.md}, \codepath{Phase-2/ADAPTERS.md}, and runtime entry \codepath{Phase-2/riscvbench.py}. Validation integration is documented through \codepath{Phase-2/tests/*} and sweep tooling in \codepath{Phase-2/sweeps/}.

\section{Design \& Architecture}
\subsection*{Function Attributes}
\begin{itemize}[leftmargin=*]
  \item \texttt{riscvbench.main()}: Inputs=CLI target/workload/flags; Outputs=normalized run artifacts + summary; Side effects=dispatches target-specific execution; Failure modes=toolchain missing, non-zero target exits.
  \item \texttt{validate\_state\_df()}: Inputs=state interval DataFrame; Outputs=schema-valid state DataFrame; Side effects=normalizes dtypes/validates values; Failure modes=missing columns, invalid state labels, bad intervals.
  \item \texttt{validate\_resid\_df()}: Inputs=residency interval DataFrame; Outputs=schema-valid residency DataFrame; Side effects=filters resident intervals and validates spans; Failure modes=missing columns, bad interval bounds.
  \item \texttt{sit\_engine\_phase1.main()}: Inputs=trace/state/residency inputs + config; Outputs=run\_windows.csv + run\_summary.json; Side effects=computes windows and summary metrics; Failure modes=input contract mismatch, empty/invalid windows.
\end{itemize}
