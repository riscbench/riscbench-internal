\section{Technical Description}
Golden traces are reproducible baseline inputs generated from deterministic micro-kernel runs, used to anchor replay correctness and regression detection.

\section{Implementation Fulfillment}
Generated using \codepath{Phase-2/tests/run_spike_golden_pipeline.py}, \codepath{Phase-2/tests/run_qemu_golden_pipeline.py}, and target execution via \texttt{riscvbench.main()}.

\section{Design \& Architecture}
\subsection*{Function Attributes}
\begin{itemize}[leftmargin=*]
  \item \texttt{run\_spike\_golden\_pipeline.main()}: Inputs=workload matrix + flags + sizes; Outputs=spike trace bundle + manifest; Side effects=orchestrates spike golden matrix; Failure modes=tool missing, run failure.
  \item \texttt{run\_qemu\_golden\_pipeline.main()}: Inputs=workload matrix + flags + sizes; Outputs=qemu trace bundle + manifest; Side effects=orchestrates qemu golden matrix; Failure modes=qemu exit/pipeline failure.
  \item \texttt{build\_manifest()}: Inputs=trace paths + mask paths + window; Outputs=manifest JSON; Side effects=pins replay inputs; Failure modes=invalid path/schema.
  \item \texttt{run\_golden\_suite.main()}: Inputs=manifest + outdir; Outputs=golden windows/summaries; Side effects=validates trace replay utility; Failure modes=invariant/replay failure.
\end{itemize}
