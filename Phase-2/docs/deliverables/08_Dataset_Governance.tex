\section{Technical Description}
Dataset governance defines provenance, immutability, versioning, and review policy for golden traces, residency masks, and replay manifests. It ensures regression baselines are auditable and intentional.

\section{Implementation Fulfillment}
Current implementation baseline exists in:
\begin{itemize}[leftmargin=*]
  \item dataset roots: \codepath{Phase-2/datasets/traces/}, \codepath{Phase-2/datasets/residency/},
  \item manifest contract: \codepath{Phase-2/datasets/manifest.json} (with \texttt{dataset\_version}),
  \item replay consumers: \codepath{Phase-2/tests/run_golden_suite.py}, \codepath{Phase-2/tests/check_determinism.py}.
\end{itemize}
Known gap: dedicated governance policy doc \codepath{Phase-2/DATASETS.md} is not yet present.

\section{Design \& Architecture}
Governance architecture should enforce:
\begin{itemize}[leftmargin=*]
  \item explicit dataset version bump on trace/mask changes,
  \item owner/reviewer approval for baseline modifications,
  \item replay checks as mandatory gate for manifest updates.
\end{itemize}
This layer is policy-oriented and must remain orthogonal to engine math and adapter parsing.
