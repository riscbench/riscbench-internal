\section{Technical Description}
Parameter sweep runner executes controlled matrix experiments over target/workload/simulator knobs, capturing case-level runtime and pass/fail outcomes without contaminating engine schema outputs.

\section{Implementation Fulfillment}
Implemented by:
\begin{itemize}[leftmargin=*]
  \item sweep engine: \codepath{Phase-2/sweeps/run_param_sweep.py},
  \item sample config: \codepath{Phase-2/sweeps/sweep_config_example.json},
  \item result visualizer: \codepath{Phase-2/sweeps/visualize_sweep_results.py}.
\end{itemize}
Output staging uses timestamped directories under \codepath{Phase-2/sweeps/results/} with per-case logs, \codepath{sweep\_results.csv}, and \codepath{summary.json}.

\section{Design \& Architecture}
Sweep architecture is config-driven:
\begin{itemize}[leftmargin=*]
  \item \texttt{shared} parameters define common run controls,
  \item \texttt{matrix} expands Cartesian case combinations,
  \item each case invokes \codepath{riscvbench.py} as a subprocess.
\end{itemize}
Metadata stays in sweep result artifacts and does not modify SIT schema contract.
